## **Context と System Prompt の使い方**

LLM ノードを設定する際、**コンテキスト（Context）** と **システムプロンプト（System Prompt）** のどちらにも指示を含められますが、用途が異なり、明確な優先順位があります。

### **コンテキスト（Context）**

> 用途：動的な入力変数を設定します。モデルの「作業エリア」、つまりモデルが現在参照している内容と考えてください。

**注意事項：**

* **コンテキスト** 欄では、**クエリのテキスト**、**ユーザーの入力**、**前のノードのデータ** を渡します。
* `${start.query}` や `${llm-nodeA.result}` などの変数を使うと、回答をよりパーソナライズしたり、状況に合わせたりできます。
* 短い指示を入れることもできますが、コンテキスト欄は動作のルールではなく **内容** を中心にしてください。

### **システムプロンプト（System Prompt）**

> 用途：モデルの動作と役割を定義します。このノードの「恒久的な職務記述書」と考えてください。

**注意事項：**

* モデルが **誰なのか**、**どう振る舞うべきか**、**何を達成すべきか** を定義します。
* システムプロンプトの指示は、コンテキスト内の指示より **優先** されます。
* 次の点は常に明確に定義することをおすすめします。
  * **役割**（例：プロダクトマネージャー、アナリスト、講師）
  * **タスクの目標**（例：レポートの作成、コードの説明）
  * **口調**（例：フォーマル、親しみやすい）
  * **ツールの使用ルール**（ツールを追加している場合）

### **ファイル処理（File Handling）**

**ファイル処理** の設定では、Agent がワークスペースでアップロードされたファイルをどう処理するかを定義できます。Agent が会話の中でファイルの内容（PDF、DOCX、画像など）を解釈・変換・抽出する必要がある場合に特に便利です。
