# ナレッジの管理

## **データセット**

**データセット** の設定ページでは、ファイルのアップロードと管理を行えます。AI Studio が対応しているファイルの種類は次のとおりです。

* 長文のテキスト（TXT、Markdown、DOCX、HTML、JSONL、画像のみではない PDF など）
* 構造化データ（CSV、Excel など）

## **データセットの追加**

### 手動で追加する

<figure><img src="../.gitbook/assets/image (22).png" alt=""><figcaption></figcaption></figure>

<figure><img src="../.gitbook/assets/image (23).png" alt=""><figcaption></figcaption></figure>

<figure><img src="../.gitbook/assets/image (25).png" alt=""><figcaption></figcaption></figure>

1. ナレッジベースのメニューで **データセット** をクリックします。
2. 画面右上の **追加** ボタンをクリックし、**+ データセット** を選択します。
3. タイトルを入力します。
4. 説明の自動生成機能を有効にするかを選択します。
   *   **「説明を自動生成」をオンにした場合**

       初めてデータセットに内容を追加すると、システムがデータセットの説明の生成をスケジュールします。その後データセットの内容を追加・削除・変更した場合も、説明の生成が再スケジュールされ、説明が現在のデータセットと一致するように保たれます。説明はスケジュールで処理されるため、データセットの変更後、更新が完了するまでに時間がかかる場合があります。
   *   **「説明を自動生成」をオフにした場合**

       **説明** 欄が表示され、データセットの説明をユーザー自身で入力・編集できます。その後データセットの内容が変更されても、この欄は自動的に更新されません。

1. **ナレッジ設定メニュー** の _データセット_ をクリックします。
2. **追加／インポート** ボタンをクリックし、_ファイルのインポート_ を選択します。
3. **アップロードエリア** をクリックしてシステムのウィンドウを開き、アップロードするファイルを選択して _次へ_ をクリックします。
4. 処理モードとして、自動処理または手動処理を選択します。自動処理を選ぶとステップ 6 に、手動処理を選ぶとステップ 5 に進みます。
5. データの処理では、左側の **ファイル処理** でファイルの内容を分割する方法を選び、_チャンクの生成_ をクリックすると、右側に分割後のデータのプレビューが表示されます。処理方法を確認したら _次へ_ をクリックします。
6. 内容をもう一度確認し、**アップロード** ボタンをクリックしてファイルをアップロードします。
7. データセットの一覧に戻り、ファイルのステータス欄が **完了** になるとデータを利用できるようになります。

### ファイルのアップロード制限

データ処理の性能とインデックスの品質を保つため、データセットへのファイルのインポートには次の制限があります。

| 項目                | 制限              |
| ----------------- | --------------- |
| 1 回にインポートできるファイル数 | 最大 **100** ファイル |
| 1 ファイルの最大サイズ      | **300 MB**      |

補足：

* 上記のいずれかの制限を超えると、メッセージが表示されアップロードがブロックされます。ファイル数を調整するか、ファイルを分割してから再度インポートしてください。
* 長い PDF や DOCX などの大きなドキュメントは、処理時間が長くなりすぎないよう、不要な画像や付録を事前に削除することをおすすめします。

#### プレビューとダウンロードのアクセス制御

元のドキュメントのプレビュー権限とダウンロード権限は別々に管理されています。元のドキュメントを閲覧したり内容をプレビューしたりできても、元のファイルをダウンロードできるとは限りません。

* ダウンロード権限を持つユーザー：画面に表示される操作ボタンから、データセット一覧、チャンクの表示、またはソースの入口から元のファイルをダウンロードできます。
* プレビュー権限のみを持つユーザー、またはダウンロード権限がないユーザー：画面の機能に応じてソースの内容をプレビューできますが、ソースの入口から元のファイルを取得することはできません。ダウンロードの入口が表示されない、または操作できない場合があります。

ほかのユーザーにデータセットのファイルのダウンロードを許可するには、管理者が **データセットの権限** で対象のデータセットにアクセスできる組織またはユーザーを追加し、設定を保存する必要があります。操作方法は 権限の操作－Object のアクセス権限 を参照してください。

#### トラブルシューティング：権限設定の表示に問題がある場合

**データセットの権限** ページで、権限の詳細が表示されない、ブロックが空白になる、展開しても内容がない場合は、次の順に試してください。

1. **更新** をクリックして一覧を再読み込みするか、ほかのメニューに切り替えてから戻ります。
2. 左側の **データセット** エリアで、対象のファイル／データセットが選択されているかを確認します。
3. 現在のアカウントが「AI Studio 管理者／AI Studio ドメインユーザー／ナレッジベース一覧管理者／ナレッジ管理者／ナレッジ編集者」など、そのナレッジを管理できる権限を持っているかを確認します。権限がない場合は、管理者に連絡してサポートを依頼してください。

## **データセット追加時のデータ処理**

ファイルのアップロード後のデータ処理には、次の 2 つの形式があります。

* **直接分割**：ユーザーが選んだオプションに従って分割します。
* **QA 分割**：Q\&A 形式のドキュメントを、質問ごとに分割します。

#### **直接分割**

元の内容に明確な質問と回答の構造がない場合や、すばやくデータのチャンクを作成したい場合は、**直接分割** モードを使います。システムが設定に従って自動的に段落を分割します。

<table><thead><tr><th width="180">処理方法</th><th>説明</th></tr></thead><tbody><tr><td>自動</td><td>既定では、入力内容の長さと言語の構造に応じて自動的に分割します。独自のルールが不要で、すぐに使い始めたい場合に適しています。分割方法を指定しない場合は、改行や句点などの一般的な記号で最初の分割を行います。</td></tr><tr><td>Token 分割</td><td>設定した分割の Token 長に従ってテキストを分割します。意味が途切れたり文脈が切れたりしないよう、1 チャンクの長さは 100〜1000 tokens の範囲にすることをおすすめします。</td></tr><tr><td>カスタムルール</td><td>より細かく制御できます。チャンクの長さ（推奨 100〜1000）と重なりの範囲（100 tokens など）の設定に加え、区切り文字のオプションで分割を制御できます。</td></tr><tr><td>Regex 分割</td><td>特定の文字（<code>\\n</code>、<code>。</code>、<code>,</code>、<code>;</code> など）でテキストを分割します。複数の記号を組み合わせて使え、一般的な自然言語処理のシナリオに適しています。</td></tr></tbody></table>

<table><thead><tr><th width="180">処理方法のオプション</th><th width="200">適用される分割方法</th><th>説明</th></tr></thead><tbody><tr><td>理想的なチャンク長</td><td>Token 分割、カスタムルール</td><td>各チャンクの目標の長さ（Token 単位）を設定します。値が小さいほど細かく分割されますが、文脈のつながりが弱くなる可能性があります。値を大きくする場合は、重なりの範囲と組み合わせて文脈の一貫性を保ちます。</td></tr><tr><td>重なりの範囲</td><td>Token 分割、カスタムルール</td><td>各チャンクが前のチャンクと重複する Token 数（100 など）を定義し、文脈の連続性を高めます。推奨値は 1 から「理想的なチャンク長 - 1」の間です。複数ターンの会話や技術文書など、文脈への依存度が高い内容に適しています。</td></tr><tr><td>カスタム区切り文字</td><td>カスタムルール</td><td>分割位置を識別する記号をセミコロン区切りで設定します。例：<code>;; ;'';</code> と設定すると、文中に <code>;</code>、<code>(スペース)</code>、<code>''</code> が現れた位置で分割されます。</td></tr><tr><td>ルール</td><td>Regex 分割</td><td>分割に使う Regex 構文を自由に定義できます。下の既定の分割例をクリックして編集できます：<code>.+\\n?</code>（改行で分割）、<code>[^。]+。?</code>（句点で分割）。</td></tr><tr><td>末尾の改行を削除</td><td>Regex 分割</td><td>チャンク末尾の空行 <code>\\n$</code> を自動的に削除するかどうかを設定します。</td></tr></tbody></table>

> おすすめ：Token 分割と重なりの範囲を組み合わせると、意味と文脈を効果的に保ち、文が途中で切れて情報が失われるのを防げます。

#### **QA 分割**

FAQ、カスタマーサポートの記録、インタビュー原稿などの Q&A 形式のドキュメントを処理する場合は、QA 分割の設定で構造の識別と意味の明確さを高められます。システムには、質問と回答のブロックを識別・分割するための次のパラメーターがあります。

<table><thead><tr><th width="200">オプション</th><th>説明</th></tr></thead><tbody><tr><td>質問のプレフィックス</td><td>質問の先頭を示す文字列（<code>Q:</code>、<code>質問：</code> など）を指定します。システムはこれを新しい質問ブロックの開始位置として扱います。</td></tr><tr><td>回答のプレフィックス</td><td>回答の先頭を示す文字列（<code>A:</code>、<code>回答：</code> など）を指定し、質問に対応する回答の内容を示します。</td></tr><tr><td>プレフィックスの削除</td><td>有効にすると、質問と回答のブロックの先頭にある識別文字列（<code>Q:</code>、<code>A:</code> など）を自動的に削除します。</td></tr><tr><td>プレフィックスの表現式</td><td>正規表現（Regex）を使った質問と回答のプレフィックスの識別に対応しています。形式が一定でない場合や大量のデータを変換する場合に適しています。例：<code>^Q[0-9]*:</code> で番号付きの質問に一致させられます。</td></tr><tr><td>末尾の改行を削除</td><td>有効にすると、各 QA ブロックの末尾にある余分な改行を自動的に削除します。</td></tr></tbody></table>

データセットを作成した後、Testing 機能で質問して、回答の生成時にどのチャンクの内容が引用されたかを確認できます。検索パラメーターを調整して検索結果を評価し、データの内容を改善して引用の正確さを高められます。

<figure><img src="../.gitbook/assets/image (49).png" alt=""><figcaption></figcaption></figure>

<figure><img src="../.gitbook/assets/image (51).png" alt=""><figcaption></figcaption></figure>

1. **ナレッジベース** の **Testing** をクリックします。

3. **再ランキングモデル** メニューで使用するモデルを選択します。
4. **確認** ボタンをクリックしてパラメーターの設定を保存します。

> 注意：Testing タブで設定した検索パラメーターは一時的に保持されます。ページを離れて（一覧ページに切り替えるなど）同じナレッジの Testing タブに戻ると、前回設定したパラメーターが読み込まれます。これらのパラメーターはテスト専用で、Agent の設定には影響しません。

### 再現と再ランキング

<figure><img src="../.gitbook/assets/image (52).png" alt=""><figcaption></figcaption></figure>

ナレッジ検索は、まず「再現」、次に「再ランキング」の 2 段階で行われ、検索の網羅性と正確さの両立を図ります。

* **再現（Retrieval）**：第 1 段階では、意味の類似度に基づいて、質問に関連する可能性のある内容をナレッジベースからまとめて見つけます。この段階では網羅性を重視し、役に立つ可能性のある資料をできるだけ見落とさないようにします。
* **再ランキング（Rerank）**：第 2 段階では、前の段階で見つかった各内容と質問との関連度を LLM モデルが 1 件ずつ評価して順位を並べ替え、最も関連性の高い内容だけを回答の根拠として残します。

| 段階             | 目的      | 説明                                              |
| -------------- | ------- | ----------------------------------------------- |
| 再現（Retrieval）  | 網羅性を高める | 意味の類似度（ベクトル検索）に基づいて、関連する可能性のある内容をナレッジベースから幅広く見つけます     |
| 再ランキング（Rerank） | 正確さを高める | LLM モデルが各内容の関連度を評価して並べ替え、最も関連性の高いチャンクを残します               |

> 備考：再現は検索の網羅性を、再ランキングは結果の正確さを重視します。両者は役割を分担しており、再ランキングがないと検索結果の正確さが下がることがあります。
