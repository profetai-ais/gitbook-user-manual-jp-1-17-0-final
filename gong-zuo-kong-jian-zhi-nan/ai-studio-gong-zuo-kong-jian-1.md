# 会話

## ページの概要

画面は主に 2 つの部分で構成されています。

* **会話履歴**：新しい会話を始めたり、以前の会話にすばやく戻ったりできます。
* **チャットエリア**：Agent と会話する場所です。

> 注意：以下のスクリーンショットは参考用です。実際の会話履歴、Agent、プロンプトテンプレートは、お使いの環境によって異なる場合があります。

会話履歴エリアは 2 つに分かれています。

* **最近の会話**：作成済みの会話スレッドが保存されます。スレッドをクリックすると、チャットエリアで開きます。
* **最近の Agent**：これまでに会話した Agent が表示されます。

### 会話のステータス表示

最近の会話一覧では、各会話の右側にアイコンで現在のステータスが表示されます。

| アイコン | ステータス       | 説明                                                                                                                  |
| ---- | ----------- | ------------------------------------------------------------------------------------------------------------------- |
| 回転   | Agent が回答中  | 回答中にほかの会話やページに切り替えても、戻ると最新の進行状況が表示されます。ページを再読み込みしても回転アイコンは残ります。回答が完了すると自動的に止まります。                                   |
| 緑の点  | 未読の回答あり     | 会話を開いていない間に Agent の回答が完了すると、緑の点が表示されます。その会話を開き、最新の回答の位置まで表示すると緑の点は消えます。                                           |
| アイコンなし | 通常        | 会話にマウスカーソルを合わせると「…」メニューが表示されます。                                                                                     |

### Session ID をコピーする

問題を報告する際に会話の Session ID を伝えると、管理者が会話ログで同じ会話を見つけやすくなります。

1. 左側の「最近の会話」または「お気に入り」フォルダー内の会話にマウスを合わせ、「…」メニューをクリックします。
2. 「Session ID」をクリックすると、その会話の Session ID がクリップボードにコピーされ、「内容がクリップボードにコピーされました。」と表示されます。

## 待機と実行枠の上限

システムは、同時に実行できる Agent の数（実行枠）を制限しています。枠には Assistant と Workforce の 2 種類があり、Agent がどちらを使うかは Agent の設定によって決まります。詳しくは [Workforce モニター](../fen-xi-zhi-nan/workforce-jian-kong.md#assistant-yu-workforce-de-cha-yi) を参照してください。枠を使い切ると、リクエストは待機になるか、後でもう一度試すよう案内されます。これはシステムの障害ではありません。

### チャットの待機

メッセージを送信したときに枠が上限に達している場合、会話はまず **待機中** になり、現在の待機順位と待機時間が表示されます。順番が来ると Agent が自動的に回答を始めるため、メッセージを再送信する必要はありません。通常のチャットと Web App のチャットの両方が対象です。

* 待機順位が 1 の場合は、次に順番が来ることを示します。
* 待機中にタブを閉じたりリクエストを取り消したりすると、そのリクエストは待機列から外れるため、再度送信する必要があります。

待機を経ても実行できなかった場合は、次のいずれかになります。

| 状況 | 説明 | 対処方法 |
| -- | -- | ---- |
| **待機時間が長すぎる** | しばらく待機しても枠を確保できなかった | しばらくしてからもう一度送信してください |
| **待機列に入れない** | 待機している人数が上限に達しており、リクエストを待機列に追加できなかった | 現在利用者が多いため、しばらくしてからもう一度お試しください |

> 待機の上限時間はシステムの設定によって決まります。チャットでの失敗の表示は、ほかの使用制限が原因の場合もあり、必ずしも枠の上限によるものとは限りません。

### 「枠が上限に達しています」の表示

次の操作は待機されません。枠が上限に達している場合は、すぐに「枠が上限に達しています」と表示されます。

* メッセージを編集した後の回答の再生成
* Workflow のジョブの作成
* マルチ Agent の会話
* 人による介入カードへの回答

この表示は、現在すべての実行枠が使用中であることを示しており、システムの障害ではありません。実行中のジョブが終わるのを待ってから、もう一度お試しください。

#### 人による介入カード

人による介入カードに回答したときに枠が上限に達している場合、回答は **まだ送信されていません**。カードは入力待ちの状態に戻り、カード自体は引き続き有効です。しばらくしてからもう一度送信してください。

### マルチ Agent の会話

マルチ Agent の会話は、選択した Agent の数と同じ数の枠を同時に確保できた場合にのみ開始されます。たとえば 3 つの Agent を選択した場合は、3 つの枠が同時に空いている必要があります。枠が足りない場合は次の 2 種類の表示があり、それぞれ対処方法が異なります。

| 表示 | 説明 | 対処方法 |
| -- | -- | ---- |
| **枠が上限に達しています** | 現在利用できる枠が足りません。ほかのジョブが終了すると枠が空きます | しばらくしてからもう一度お試しください |
| **選択数が上限を超えています** | 選択した Agent の数が、プランで同時に実行できる上限を超えています。ほかのジョブが実行されていなくても開始できません | 選択する Agent の数を減らしてください。時間をおいても解決しません |

## **ファイルをアップロードして内容を分析する**

<figure><img src="../.gitbook/assets/image (81).png" alt=""><figcaption></figcaption></figure>

<figure><img src="../.gitbook/assets/image (82).png" alt=""><figcaption></figcaption></figure>

会話ページではさまざまな形式のファイルをアップロードできますが、アップロードに成功しても、その内容を Agent が必ず読み取り・分析できるとは限りません。実際に処理できる内容は、使用するモデルの能力、ファイル形式、ファイルの内容によって異なります。

アップロード後、Agent はファイルを読み取れるかを判断し、ユーザーの指示に従って要約、内容の整理、文字起こしなどを行います。モデルがそのファイルを処理できない場合は、読み取りや分析ができない旨を会話内で回答します。

## **会話内のファイル**

<figure><img src="../.gitbook/assets/image (548).png" alt=""><figcaption></figcaption></figure>

Agent との会話では 2 種類のファイルが扱われます。「ファイル」アイコン内のファイルアイコンをクリックすると **表示** でき、権限に応じて **ダウンロード** や **削除** も行えます。

* **参照ファイル**：ユーザーがプロンプトの添付としてアップロードしたファイルです。
* **作業ファイル**：Agent が回答や出力の中で生成したファイルです。

### 同じ会話でアップロード済みのファイルを使う

入力欄の **参照ファイル** 一覧で過去にアップロードしたファイルにチェックを入れると、再アップロードしなくても Agent がそのまま再利用できます。

<figure><img src="../.gitbook/assets/image (545).png" alt=""><figcaption></figcaption></figure>

<figure><img src="../.gitbook/assets/image (546).png" alt=""><figcaption></figcaption></figure>

<figure><img src="../.gitbook/assets/image (547).png" alt=""><figcaption></figcaption></figure>

同じ会話の中で、以前アップロードしたドキュメントを参考資料として選び直せます。

手順：

1. 会話ページ右上の **その他** アイコンをクリックします。
2. ファイルパネルで **作業ファイル** に切り替えます。
3. 再利用するドキュメントにチェックを入れます。
4. ドキュメントが会話の入力欄に表示され、指示を入力すると再び参照できます。

使わないドキュメントは、ファイルのタグの横にある「×」をクリックして削除できます。

### 会話内のファイルをダウンロードする

Agent が以前提供したファイルをもう一度取得したい場合は、元の会話を開き、Agent の回答に添付されたダウンロードリンクを直接クリックします。ファイル一覧を別に開く必要はありません。

<figure><img src="../.gitbook/assets/image (549).png" alt=""><figcaption></figcaption></figure>

<figure><img src="../.gitbook/assets/image (550).png" alt=""><figcaption></figcaption></figure>

手順：

1. 会話ページ右上の **その他** アイコンをクリックします。
2. ダウンロードしたいファイルのダウンロードアイコンをクリックします。

### 作業ファイルを共有する

Agent が生成した作業ファイルはほかの人と共有できます。共有するとリンクが作成され、相手はブラウザーで開くだけでファイルを確認できます。HTML ファイルはそのまま Web ページとして表示され、Markdown ファイルはレイアウトを適用した内容で表示されます。

手順：

1. 会話ページ右上の **その他** アイコンをクリックします。
2. ファイルパネルで **作業ファイル** に切り替えます。
3. 共有したいファイルの横にある共有アイコンをクリックし、共有リンクをコピーします。

#### リンクの有効期限

| 設定     | 説明                              |
| ------ | ------------------------------- |
| 既定     | リンクは作成から 1 か月間有効で、期限を過ぎると開けなくなります。 |
| 期限を延長  | リンクの有効期間を手動で延長できます。             |
| 無期限で公開 | リンクが期限切れにならず、常に開けるように設定できます。    |

> 注意：リンクを知っていれば誰でもファイルを開けます。共有する前に、ファイルの内容を公開してよいかを確認し、必要に応じて適切な有効期限を設定してください。**無期限で公開** は慎重に使用してください。

### ダウンロードとアクセス権限について

ファイルをダウンロードする際、システムはログイン状態、Agent の利用権限、ファイルのダウンロード権限をそれぞれ確認します。この 3 つの権限は役割が異なり、Agent を開いたり利用したりできても、その Agent が参照または生成したすべてのファイルをダウンロードできるとは限りません。

<table><thead><tr><th width="222">確認項目</th><th>説明</th></tr></thead><tbody><tr><td><strong>ログイン状態</strong></td><td>ユーザーがログインし、本人確認が完了しているかを確認します。ログインがタイムアウトした場合や本人確認が完了していない場合、ダウンロード機能が一時的に使えないことがあります。</td></tr><tr><td><strong>Agent の利用権限</strong></td><td>ユーザーが Agent を開けるか、その Agent の会話履歴と関連ファイルにアクセスできるかを決めます。</td></tr><tr><td><strong>ファイルのダウンロード権限</strong></td><td>ユーザーがナレッジベース、データセット、または Agent が生成した作業ファイルをダウンロードできるかを決めます。ファイルの出所と最新の権限設定に基づいて判定されます。</td></tr></tbody></table>

#### ナレッジベースとデータセットのドキュメント

ダウンロードのアクセス制御は、ファイルの出所であるナレッジベースまたはデータセットのレベルで適用されます。ある Agent を開いて利用できても、その Agent が参照している元のドキュメントをダウンロードする権限があるとは限りません。

たとえば、Agent を通じてあるナレッジベースの内容を検索できても、そのナレッジベースのダウンロード権限がなければ、元のドキュメントを直接ダウンロードすることはできません。

つまり、管理されたナレッジベースやデータセットのファイルは、その出所のルールに従ってダウンロード権限が判定され、ファイルが見えるすべての人がダウンロードできるわけではありません。

#### Agent が生成した作業ファイル

Agent が会話の中で生成したレポート、整理結果、そのほかの作業ファイルも、ファイルの出所とユーザーの現在の権限に基づいてダウンロードできるかが判定されます。

作業ファイルが管理されたナレッジベースやデータセットの内容を参照している場合、同じダウンロードルールが適用されます。Agent の回答にダウンロードリンクが表示されていても、関連する権限がなければダウンロードできないことがあります。

たとえば、Agent が管理されたナレッジベースをもとに整理レポートを生成したとします。ユーザーは Agent のテキスト回答を閲覧できますが、そのレポートをダウンロードする際には、対応するダウンロード権限があるかどうかが確認されます。

#### よくある権限のケース

<table><thead><tr><th width="306">ケース</th><th>システムの動作</th></tr></thead><tbody><tr><td><strong>未ログイン、ログインのタイムアウト、または本人確認が未完了</strong></td><td>一時的なアクセス制限です。ダウンロードがブロックされたり、ダウンロードの入口が非表示になったり、権限がない旨のメッセージが表示されたりすることがあります。再ログインすると元の権限がそのまま使えるようになり、既存の会話やファイルが消えることはありません。</td></tr><tr><td><strong>ファイルのダウンロード権限が削除または変更された</strong></td><td>再ログインしても元のダウンロード権限は戻りません。Agent の利用や会話の閲覧はできても、管理されたドキュメントや関連する作業ファイルは、権限が再付与されるまでダウンロードできません。</td></tr><tr><td><strong>Agent の利用権限が削除された</strong></td><td>その Agent を開けなくなり、その Agent の既存の会話履歴やファイルにもアクセスできなくなります。再ログインしても権限は戻らず、管理者による再付与が必要です。</td></tr><tr><td><strong>ログインと関連する権限がすべて有効</strong></td><td>ファイル一覧または会話履歴のダウンロードリンクからファイルを取得できます。</td></tr></tbody></table>

## 回答内の引用元

<figure><img src="../.gitbook/assets/image (37).png" alt=""><figcaption></figcaption></figure>

Agent の回答が外部の Web ページ、ナレッジベース、ファイルを引用している場合、回答に引用元へのクイックリンクが表示され、クリックすると引用元の内容を開けます。引用元には次の種類があります。

| 引用元の種類       | 説明                                |
| ------------ | --------------------------------- |
| Web ページ      | インターネット検索で見つかった Web ページ           |
| ナレッジベース      | Agent がナレッジベースから引用したドキュメント        |
| アップロードしたファイル | ユーザーが会話でアップロードしたファイル              |

ナレッジベースの引用元を表示するかどうかは、Agent の「チャット表示 → ナレッジベースの引用元」の設定によって決まります。詳しくは [チャット Agent](../agent-zhi-nan/liao-tian-agent.md) を参照してください。

### ナレッジベース内の画像

回答がナレッジベース内の画像を引用している場合、画像は会話内に直接表示され、ダウンロードしなくても確認できます。画像をクリックするとプレビューが開き、画像はウィンドウのサイズに合わせて元の縦横比のまま拡大縮小されます。

## ビジュアル回答

<figure><img src="../.gitbook/assets/visual-response-table.png" alt=""><figcaption></figcaption></figure>

Agent で「ビジュアル回答」がオンになっている場合、Agent は回答の内容に応じてカード、表、グラフ、フローチャートなどで表示し、テーマの配色を適用するため、情報がより見やすくなります。

* ビジュアル回答では出力される内容が多くなるため、Token 使用量と料金は通常のテキストの回答よりやや高くなります。
* オンにするかどうかは、Agent の作成者が「チャット表示」で設定します。詳しくは [チャット Agent - ビジュアル回答](../agent-zhi-nan/liao-tian-agent.md#shi-jue-hua-hui-fu) を参照してください。

## **使用クォータ**

<figure><img src="../.gitbook/assets/image (69).png" alt=""><figcaption></figcaption></figure>

**使用クォータ** エリアでは、**AI Studio のワークスペース** で AI モデルを利用した際の Token とコストの消費状況を確認できます。Token は処理される最小のデータ単位で、ユーザーの入力とモデルの出力の両方を含みます。この機能を使うと、使用状況をリアルタイムで把握・管理できます。

> 注意：既定では、クォータの使用量は毎日自動的にリセットされます。

使用状況の詳細は **2 か所** に表示され、それぞれ用途が異なります。

## Agent の回答品質へのフィードバック

Agent の個々の回答に対してフィードバックを送ることで、メモリー検索の品質と Agent の回答精度を高められます。各回答の下にフィードバックボタンが表示され、良い評価または悪い評価を選べます。

### 良い評価を送る

Agent の回答が期待どおりだった場合は、回答の下の **いいね** ボタンをクリックすると、良い評価のウィンドウが開きます。

<figure><img src="../.gitbook/assets/image (70).png" alt=""><figcaption></figcaption></figure>

良い評価のウィンドウでは、次のような理由を選べます。

* タスクを解決できた
* 指示どおりに回答した
* 回答の品質が高い
* すばやく効率的
* 自律的に実行した操作が役に立った
* その他

**詳細** 欄に、回答のどの部分が特に役に立ったか、どの部分が期待どおりだったかなどを補足することもできます。この欄は任意です。

### 悪い評価を送る

Agent の回答が期待どおりでなかった場合は、回答の下の **よくないね** ボタンをクリックすると、悪い評価のウィンドウが開きます。

<figure><img src="../.gitbook/assets/image (71).png" alt=""><figcaption></figcaption></figure>

悪い評価のウィンドウでは、次のような理由を選べます。

* 意図を誤解している
* 内容が正しくない
* 回答が不完全
* 指示どおりに回答していない
* 内容が安全でない、または不適切
* その他

**詳細** 欄に、回答の誤っている箇所、不足している情報、Agent にどう改善してほしいかなどを補足することもできます。この欄は任意です。

### 送信したフィードバックを確認する

フィードバックを送信すると、対応するボタンが選択済みの状態になります。そのボタンをもう一度クリックすると、操作メニューが開きます。

**フィードバックを表示** をクリックすると、選択した理由と補足説明を含め、送信したフィードバックの内容を確認できます。

### フィードバックを取り消す

送信したフィードバックを取り消すには、選択済みのフィードバックボタンをクリックし、操作メニューで **フィードバックを削除** を選びます。

削除すると、その回答はフィードバック前の状態に戻り、改めて良い評価または悪い評価を選べます。

> 注意：Agent の回答ごとにフィードバックは 1 回送信できます。送信済みの場合は、そのフィードバックを確認または削除してから、新しいフィードバックを送信できます。フィードバックは今後の Agent の回答品質の改善に使われるため、補足説明には、回答が期待どおりだった理由、またはそうでなかった理由を具体的に書くことをおすすめします。

## Canvas

Canvas は、AI が生成した内容を右側の作業エリアに表示し、後から確認・編集・整理しやすくする機能です。AI との会話で長い内容や複雑な内容が生成された場合、ドキュメント、表、グラフ、コード、そのほかの視覚的なコンテンツを Canvas でわかりやすいレイアウトで表示できます。

Canvas は、ドキュメントの作成、レポートの整理、データの分析、グラフの確認、会話しながら同じ内容を繰り返し修正する場合など、内容を長時間確認・調整するシナリオに適しています。左側で AI と相談しながら、右側で Canvas の内容を確認・管理できるため、チャットメッセージの中から内容を何度も探す手間が減ります。

### Canvas を呼び出す

<figure><img src="../.gitbook/assets/image (72).png" alt=""><figcaption></figcaption></figure>

<figure><img src="../.gitbook/assets/image (74).png" alt=""><figcaption></figcaption></figure>

1. 左下の「+」をクリックして Canvas を選択すると、入力欄に表示されます。
2. チャットウィンドウに要望を入力し、AI にドキュメント、表、グラフなどを生成させます。
3. Canvas で表示できる内容が生成されると、画面に Canvas カードが表示されます。
4. Canvas カードをクリックすると、内容が右側の Canvas 作業エリアに開き、既定で **プレビュー** タブが表示されます。Canvas で内容全体を確認できます。
5. 内容を調整したい場合は、チャットウィンドウで引き続き AI に修正を依頼するか、システムが対応していればキャンバスの内容を直接編集できます。修正後の内容は Canvas に表示され、続けて確認・整理できます。

> 注意：Canvas は、長い内容や複雑な内容、繰り返し確認・修正が必要な内容に適しています。短いテキストの回答は、Canvas を開かずにチャットウィンドウに直接表示されることがあります。\
> 内容の種類によって利用できる操作が異なる場合があります。たとえばドキュメント、表、グラフ、コードでは表示や編集の方法が異なることがあります。Canvas の内容は AI が生成したものなので、利用する前に内容が正しいかを改めて確認し、必要に応じて AI に修正や補足を依頼してください。

インターネット検索の結果、マインドマップ、ナレッジベースの引用を開いても、Canvas は折りたたまれるだけで内容は消去されません。全幅表示の Canvas を閉じると、次に開いたときは通常の幅に戻ります。

## 音声・動画ファイルをアップロードして内容を分析する

会話ページでは MP4、MP3 などの音声ファイルをアップロードできます。Agent はファイル内の話し声を読み取り、ユーザーの指示に従って内容を整理します。

アップロード後、Agent に次のようなことを依頼できます。

* 音声の内容を文字起こしする
* 動画や録音の要点を要約する
* 会議の結論と ToDo を整理する
* 議論のテーマ、課題、決定事項をまとめる
* 内容を議事録、レポート、またはそのほか指定した形式に書き直す

### 操作方法

<figure><img src="../.gitbook/assets/image (554).png" alt=""><figcaption></figcaption></figure>

<figure><img src="../.gitbook/assets/image (555).png" alt=""><figcaption></figcaption></figure>

1. 会話の入力欄で音声・動画ファイルをアップロードします。
2. アップロードが完了するまで待ちます。
3. Agent に実行してほしい指示を入力します。
4. Agent がファイル内の会話を読み取り、指定した形式で結果を生成します。

### 指示の例

* 「この録音を文字起こししてください。」
* 「この動画の主な内容を要約してください。」
* 「会議の結論、ToDo、担当者を整理してください。」
* 「会話の内容を正式な議事録にまとめてください。」
* 「動画で挙げられた課題と改善案を一覧にしてください。」

### MP4 動画ファイルについて

* 会話ページでは MP4 動画をアップロードできます。Agent は動画内の音声を読み取って分析し、文字起こし、要約、議事録の作成に利用できますが、動画の映像は認識・分析しません。
* MP4 ファイルに音声が含まれていない場合、Agent は分析できる内容を取得できません。

### 注意事項

認識結果は、録音の品質、背景の雑音、話す速さ、複数人の同時発言、専門用語などの影響を受けることがあります。文字起こしや議事録を作成した場合は、人名、数値、重要な決定事項などが正しいかを確認することをおすすめします。

## 音声入力

音声入力機能を使うと、話すだけで文字を入力できます。マイクをオンにして話し始めると、システムが音声をテキストに変換するため、手入力の時間が減り、データの記入や文字入力の効率が上がります。

<figure><img src="../.gitbook/assets/image (61).png" alt=""><figcaption></figcaption></figure>

<figure><img src="../.gitbook/assets/image (65).png" alt=""><figcaption></figcaption></figure>

<figure><img src="../.gitbook/assets/image (66).png" alt=""><figcaption></figcaption></figure>

<figure><img src="../.gitbook/assets/image (67).png" alt=""><figcaption></figcaption></figure>

1. 「+」をクリックします。
2. **録音** を選択します。
3. **音声ソースの選択** ウィンドウで録音元を選択します。
   * マイク：マイクが拾う話し声と周囲の音を録音します。
   * システム音声：オンライン会議、動画、そのほかのアプリケーションの音声など、パソコンで再生されている音を録音します。パソコンで再生中の音を録音する場合は **システム音声** を選択します。
4. ブラウザーで共有元を選ぶウィンドウが開きます。音声を再生しているブラウザーのタブ、アプリケーションのウィンドウ、または画面を選択します。
5. **システム音声を共有** をオンにして、選択した共有元の音声を取り込めるようにします。
6. **音声を共有** をクリックして、システム音声の録音を開始します。
7. 録音が始まると、画面下部に録音コントロールバーが表示されます。
   * **一時停止** ボタンをクリックすると、録音を一時停止します。
   * **チェック** ボタンをクリックすると、録音を完了します。
   * 左側の「×」をクリックすると、今回の録音を取り消します。

> 注意：音声認識の精度を高めるため、静かな環境で、はっきりと一定の速さで話すことをおすすめします。周囲の雑音が多い、話す速度が速すぎる、発音が不明瞭といった場合は、認識結果に影響することがあります。\
> 音声の変換には少し時間がかかります。確認ボタンをクリックした後、変換が完了するまでお待ちください。変換されたテキストには誤字、脱字、句読点の不足などが含まれる場合があるため、送信前に必ず内容を確認してください。

## よくある質問

<details>

<summary>誤って会話を削除してしまいました。元に戻せますか？</summary>

できません。会話は削除すると元に戻せず、管理者が権限で復元することもできないため、権限の申請や窓口への連絡は不要です。

補足：会話が削除された後も、その Agent の管理者と編集者は Agent の **会話ログ** でその会話の記録を確認できますが、ワークスペースに復元することはできません。

</details>
